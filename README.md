# 100x AI Voice Agent — Meet My AI Twin

An interview demo with **FastAPI + Gemini + MongoDB Atlas + uv**, and a plain HTML/CSS/JS frontend. Browser speech recognition captures questions; browser speech synthesis reads responses aloud. Guests can chat without registration. Registered users get saved history on the server.

## 1. Requirements

- Python 3.12 and [uv](https://docs.astral.sh/uv/getting-started/installation/)
- A MongoDB Atlas cluster and database user
- A Gemini API key from [Google AI Studio](https://aistudio.google.com/app/apikey)
- Optional Google Cloud OAuth 2.0 Web application credentials

## 2. Backend (PowerShell)

```powershell
cd backend
uv lock
uv sync
Copy-Item .env.example .env
```

Edit `backend/.env` with your actual MongoDB URI, Gemini key, and a unique JWT secret (32+ characters). Never commit `.env`. Generate a secret with `uv run python -c "import secrets; print(secrets.token_urlsafe(48))"`.

```powershell
uv run uvicorn app.main:app --reload --port 8000
```

Check `http://localhost:8000/health` and `http://localhost:8000/docs`.

**Important:** `uv.lock` is generated by `uv lock` during setup. Commit it before Render deployment. This ZIP does not include a pre-resolved lockfile.

## 3. Frontend

In a second terminal:

```powershell
cd frontend
py -3.12 -m http.server 5500
```

Open `http://localhost:5500`. `frontend/config.js` defaults to `http://localhost:8000`.

If your local frontend runs at a different origin, add it to `CORS_ORIGINS` in `backend/.env` and restart the API.

## 4. Google sign-in (optional)

Create a Google OAuth **Web application** in Google Cloud Console. Add authorized redirect URI `http://localhost:8000/api/auth/google/callback`. Put the client ID and secret into `.env`. OAuth starts at `/api/auth/google/start`, returns to the backend callback, then redirects to the frontend with a short-lived, single-use exchange code. **Do not** expose the Google client secret to the frontend. Google login is unavailable until credentials are configured; email/password and guest access still work.

For production, set `GOOGLE_REDIRECT_URI=https://YOUR-RENDER-URL/api/auth/google/callback` and register this exact URI in Google Cloud Console.

## 5. Deploy

1. Commit and push to GitHub, including `backend/uv.lock` (after `uv lock`).
2. On Render, create a Python Web Service from the repository: **root directory** `backend`; **build command** `pip install uv && uv sync --frozen --no-dev`; **start command** `uv run --no-sync uvicorn app.main:app --host 0.0.0.0 --port $PORT`.
3. Add the variables from `backend/.env.example` to Render, replacing localhost values. Configure MongoDB Atlas network access to allow your backend; restrict it where your hosting arrangement permits.
4. On Vercel, import the same repository with **root directory** `frontend`, framework preset **Other**, and no build command. Set `frontend/config.js` to the public HTTPS Render API URL and commit the change before deployment.
5. Set Render `FRONTEND_URL=https://YOUR-VERCEL-DOMAIN` and `CORS_ORIGINS=https://YOUR-VERCEL-DOMAIN` (comma-separated if needed). Set Google redirect URI as above.
6. Verify guest chat, register/login, Google OAuth, voice recording, and speech playback on the deployed site. Browser speech recognition support varies; Chrome-based browsers generally work best. Use HTTPS in production for microphone permissions.

## Endpoints

- `GET /health` — readiness
- `POST /api/auth/register` — register
- `POST /api/auth/login` — login
- `GET /api/auth/me` — current account
- `GET /api/auth/google/start` — Google OAuth
- `GET /api/auth/google/callback` — OAuth callback
- `POST /api/auth/google/exchange` — exchange single-use login code
- `POST /api/chat` — ask a question; guests welcome
- `GET /api/chat/history` — authenticated history

## Before submitting the assessment

- **Edit `backend/app/prompts/personality_prompt.py`** to reflect your exact, resume-verified professional background. The included profile is a starting draft, not an independently verified biography.
- Review and customize your name, branding, answers, and resume.
- Test free-tier Gemini model access and quotas. `GEMINI_MODEL` is configurable; use a model currently available to your account.
- Guest messages are intentionally not persisted and have no previous-turn context on the backend. Signed-in sessions preserve recent context in MongoDB.
- The guest chat endpoint is public. For a real production app, add IP-based rate limiting, abuse prevention, request budgets, monitoring, and stricter data retention policies. The app is an assessment MVP, not a security-audited production system.
- Tokens are kept in `sessionStorage` for this demo. For higher security, use a carefully designed BFF or secure HTTP-only session-cookie architecture.
- Avoid claiming unverified achievements. The bot should explicitly acknowledge unknown information rather than fabricate it.
